# 游戏活动手册

七款游戏的中文国服活动日历：首页为 Game Event Deadlines 截止汇总表，可选择游戏，按活动截止时间从近到远排列，显示截止时间与实时倒计时。游戏页面按魔兽世界、最终幻想14、明日方舟：终末地、明日方舟、Fate/Grand Order、原神和崩坏：星穹铁道分开，使用连续色条月历。原有魔兽团本、大秘境和时光漫游职责攻略保留。

站点：https://edlinf.github.io/pig-game-calendar/

GitHub：https://github.com/Edlinf/pig-game-calendar （源码 `main`，静态发布 `gh-pages`）

原神页面：https://edlinf.github.io/pig-game-calendar/#genshin

崩坏：星穹铁道页面：https://edlinf.github.io/pig-game-calendar/#hsr

## 本地查看

无需安装依赖或构建。用静态 HTTP 服务打开 `dist/`，例如：

```sh
python3 -m http.server 8000 --directory dist
```

访问 `http://localhost:8000`。首页为 `#home`，游戏页为 `#wow`、`#ff14`、`#endfield`、`#arknights`、`#fgo`、`#genshin` 和 `#hsr`；原 `#calendar` 仍指向魔兽日历。

## 文件

- `dist/index.html`：页面壳与导航。
- `dist/app.js`：日历、汇总、详情和页面切换。
- `dist/games-data.js`：游戏元数据与新增活动；首页复用同一份条目。
- `dist/data.js`：原魔兽日历、团本和地下城资料。
- `dist/guides.js`：原魔兽攻略页面。
- `dist/style.css`：浅灰圆角主题与多游戏、移动端样式。
- `.openai/hosting.json`：既有 Sites 项目绑定，无凭据。
- `.openai/github-sync.json`：已核实的 GitHub 同步目标，无凭据。

## 游戏外活动筛选

首页及七个游戏日历都提供“包含游戏外活动”复选框，默认勾选。所有页面共用同一选择，并通过浏览器本地存储记住；无法使用本地存储时，仍可在当前页面会话内切换。取消勾选后，游戏外活动同时从总览、月历色条、当日活动、进行中、即将开始、已结束、近期截止和数量统计中排除。开关独立于游戏多选，不改变选中的游戏。

每个活动使用布尔字段 `externalActivity` 标明参与方式。网页福利、网页小游戏、官网抽奖、线下联动与报名、直播和站外创作投稿设为 `true`；需要游戏内任务配合、但报名或独立领奖在网页完成的活动（如黄金的试炼、官网冒险手册）也属于此类。实际在游戏内完成的节日、寻访/祈愿、挑战、商城优惠，以及在游戏内编辑并报名的创作赛事使用 `false`。不能因活动有网页介绍、奖励发进游戏或名称含“联动/创作”就自动判定类别。

现有旧条目由 `EXTERNAL_ACTIVITY_IDS` 逐项标注，关联窗口继承主体的游戏外属性。新条目应在活动数据或 `addEvent` 的 extra 中直接提供 `externalActivity: true/false`；未知不凭标题猜测，后续核对参与方式后修正。FGO目前没有已收录的游戏外条目，仍显示同一开关，以支持后续添加。所有条目继续遵守 `parentEvent` 与 `versionRoutine` 的既有排除规则，通行证等不会因打开开关重新显示。核对日期不因分类或筛选改动而刷新。

## 活动时间

不收录随版本例行更替的固定项目：通行证、纪行、千星纪游、无名勋礼、版本赛季与版本更新补偿等。已存在的历史数据标记 `versionRoutine: true`，从总览、已结束列表、各游戏月历、当日活动、进行中/即将开始和截止提醒中统一排除，未来更新也不重新添加此类条目。独立限时主题活动和双倍掉落继续收录；崩铁不收录角色/光锥跃迁及挑战轮换，其他游戏的祈愿/寻访和挑战轮换按原规则收录；不能仅凭持续时间较长或在版本末结束就判定为版本固定项目。

崩铁既有跃迁和挑战轮换条目标记 `excludedFromCalendar: true`，由 `HSR_EXCLUDED_EVENT_TYPES` 按游戏与类别设置；当前、未来和历史窗口均经 `visibleEvents` 从总览、月历、当日活动、进行中/即将开始、已结束、截止提醒和计数中排除，游戏外活动开关不能恢复它们。后续新一期不重新收录；幻宠活动、独立限时玩法、双倍掉落、网页活动和独立商城优惠沿用原规则，其他游戏不受此项排除影响。原始来源、实际核对日及活动时间保留。

所有游戏均不展示签到类活动，包括七日/十日签到、每日签到、累计登录、前瞻签到、倒计时登录及纯登录领奖福利；网页签到同样排除，当前、未来和历史已结束窗口都适用。既有条目由 `SIGNIN_EVENT_TYPES` 或 `signInActivity: true` 标记 `excludedFromCalendar: true`，关联子条目继承隐藏，游戏外活动开关不能恢复。后续不重新添加此类条目；新名称先按参与方式归类。混合纪念活动保留独立玩法、任务、养成优惠等内容，清理其中签到奖励、条件和截止说明；详情的关联提醒也排除隐藏条目。仅需登录账号参与网页任务、完成游戏任务或收取一次性邮件，不因此判定为累计签到。实际核对日期和原始活动时间不随收录规则改写。

所有显示时间为 Asia/Shanghai（UTC+8）。`startAt` / `endAt` 必须包含时区，结束时间采用排他边界。公告截至03:59的条目设为04:00关闭，显示仍保持公告原文时刻。版本解锁节点设 `milestone: true`，只在开放当天标记，不当成第二天关闭的活动。只公布日期的条目设 `datePrecision: 'day'` 与 `lastDay`，按完整日期覆盖，并明确说明未公布时刻；`deadlineLabel` 可保留官方公布的截止表述。

`boundaryDate` 用于已经公布维护日期但尚无准确时刻的条目；除下述已确定截止类别外，到维护日自动转为待复核，不宣称准确结束。终末地的版本维护前窗口使用维护日06:00，标准化后清除 `boundaryDate`，改用排他 `endAt`。关卡、兑换、寻访和专用道具过期应按不同截止时间核对；签到类活动不新增展示条目。

同一活动的兑换、领奖或网页登记条目设置 `parentEvent` 指向主体活动 ID，保留官方时间数据，但不在日历、当日列表、进行中、即将开始、截止提醒或首页统计中单独显示。主体活动详情的时间说明保留这些截止时间，避免错过奖励。与主体同刻关闭的兑换无需另建重复条目；独立领奖活动不强行关联。维护时刻未知时，不推算后续窗口。

各游戏月历采用跨日期的连续色条，跨周时在下行接续。桌面每周最多显示五行，580px及以下的手机布局最多显示三行；拥挤日期显示“另 N 项”，点日期可查看全部条目，点色条可查看完整详情。

界面采用浅灰背景、稍亮的卡片和圆角。活动横条使用14%游戏色浅底与1px同色细边框，悬停强化边框并加轻阴影；跨周续接端保持平直且不画竖向边框，待核实条目保持虚线。手机首页将截止表格转换成活动卡片，截止时间和倒计时并排显示；月历下方显示当日活动，触屏活动条与主要按钮加大点击区域。活动时间和详情使用同一份数据，不因手机排版省略条目。

首页汇总同一份活动数据，默认显示全部游戏中未结束的公告核对活动及用户授权的美服换算参考。首页和各游戏日历不提供“公告与换算排期 / 全部排期”选项，沿用原默认收录范围；保留活动状态与资料来源说明。游戏下拉框支持多选，顶部提供全选和全不选；勾选后立即筛选并保持菜单展开，全不选时显示空列表，已结束活动和资料核对同步跟随选择。菜单可点击外部或按 Esc 收起，选择在页面内切换时保留。已结束活动折叠保留。开放节点没有结束时间，不当作截止活动，在对应游戏月历查看。精确截止按排他 `endAt` 每秒更新倒计时，到期自动归入已结束；截止列保持官方原文的23:59、24:00等表述。仅公布日期的条目只显示按日期计算的天数，不生成小时、分钟或秒数。维护时刻未知时按已公布日期排序，同日排在已知时刻之后，倒计时显示待公告。未核实的参考排期不显示精确倒计时。

只公布“版本更新后”或“维护后”的开始时间，保留 `start` 作为月历覆盖日期，设置 `startAt: null` 与 `startPrecision: 'version'`，维护后的条目可设 `startPrecision: 'maintenance'`；`dateLabel` 写明版本更新后或维护后，不编造固定开服时刻。只列开始日期时使用 `startPrecision: 'day'`。

`checked` 是实际核对日期，不能因为页面发布或标题改动而批量刷新。`verification` 区分官方公告、公告转载、国服 Wiki、周常活动日历、固定月度排期与其他待核实参考。展示分类的调整不应把社区来源改写为官方公告。

## 魔兽活动排期

按用户2026-10-14的要求，周常采用美服正式服日历对应的国服周期，作为确定排期展示。实际读取 Wowhead / WoWDB 的 LIVE 美服事件记录，保留原始当地窗口、America/Los_Angeles 时区、北京时间和地区映射；时区换算处理夏令时，区域轮换按美服当地周二对应国服同周周四，不能简单把北京时间加一天。原始来源保存在 `usCalendar` 中，页面不显示换算过程或“换算参考”标签。

周常设置 `confirmed: true`，不设置 `scheduleReference`，用 `weeklyResetDate` 记录国服重置日期。`endAt` 为周四 `05:00:00+08:00`，`end` 为同日，删除 `datePrecision` / `lastDay`。在总览、详情、月历和已结束列表使用确定排期样式；05:00前仍进行中，到点立即归档，倒计时每秒更新。真实资料来源和原有核对日继续保留，参与条件、奖励及副本池以游戏内为准；不把社区日历标成国服官方公告。

暗月马戏团设置 `confirmed: true`、`scheduleRule: 'first-sunday-week'`，每月第一个周日开始，持续七个自然日。起始日期取当月首个周日，排他 `end` 为起始日期加七天，`lastDay` 为加六天；以 `datePrecision: 'day'` 展示完整日期窗口，不另编造小时。现有10月一期为10月4日至10日，11月一期为11月1日至7日。总览和月历使用确定排期样式，详情说明固定月度规则，不显示外服参考、待核实或换算标签。

其他仅有外服日期的节日条目（例如万圣节）继续设置 `confirmed: false`、`scheduleReference: 'us-calendar'`，默认显示并保留其日期参考标识，不生成时分秒倒计时。节日不套用周常偏移；官网福利按国服原始公告保留。除暗月已确定的月度规则外，不按轮换周期生成来源未公布的远期窗口。现有11个周常窗口（5期时光漫游及6个奖励周）与原始日历来源继续保留，按周复核。

## 周常与维护截止

魔兽世界国服周常于对应周四北京时间05:00结束；终末地国服版本维护前窗口截至已公布维护日北京时间06:00。`STANDARD_DEADLINE_HOURS` 保存两个时刻，匹配 `weeklyResetDate` 或终末地 `boundaryDate` 后设置排他 `endAt`、同日 `end` 与内部 `cutoffBasis: 'fixed-schedule'`，清除旧日期精度和待公告边界。终末地维护日期未知时仍等待日期，不推算下次维护日。

截止列、详情、近期提醒、当日活动、进行中列表与归档共用同一时间，支持精确倒计时。界面直接显示截止日期和钟点：魔兽周常不附“换算参考”或“统一截止”，终末地条目不附“统一截止”；数据说明、来源分类、倒计时和攻略中的旧标签也不得恢复。其他游戏、国服官网福利、终末地独立固定截止及开始时间保持各自公告值，通行证等版本固定项目继续隐藏。
